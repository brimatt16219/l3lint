# GEN-PCI-001: Card number in the payload

| Property | Value |
| --- | --- |
| Severity | error |
| Confidence | policy |
| Level | general |
| Brand | all brands |
| Impact | hygiene |
| Effective | always |
| Pack | l3lint.rules.general 1.0.0 |

## Requirement

No value may be a card number. Send only the last four digits in card.last4.

## Why

A card number puts the payload, and everyone who handles it, in PCI DSS scope. l3lint masks it before any other stage sees it.

## Check

`custom (check: CardNumber)`

## Message

`A card number was found at {field} and masked as {masked}.`

## Fix

Remove the card number; send only the last four digits in card.last4.

## Sources

- <https://www.pcisecuritystandards.org/standards/pci-dss/>
- <https://www.iso.org/standard/70484.html>

## Notes

Values in code fields (product code, commodity code, sequence) are reported as warnings, because any random 16-digit code passes the Luhn check about one time in ten.
